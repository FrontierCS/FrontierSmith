# Berland Neutral-Site League Planner

## Problem

Berland will host a new neutral-site football super league.

There are `n` teams. Every pair of teams must play exactly once, so the tournament has `n - 1` rounds and in each round every team plays exactly one match. All matches are played at neutral stadiums.

You must design the entire tournament schedule:

- decide in which round each pair of teams plays,
- assign a stadium to every match,

so as to maximize commercial value while controlling travel.

A schedule is **feasible** if:

1. every unordered pair of teams plays exactly once,
2. in every round, each team appears in exactly one match,
3. every match is assigned to a stadium available in that round,
4. no stadium hosts more than one match in the same round.

The objective mixes:

- **match value**: popular matches in good rounds and good stadiums are worth more,
- **travel cost**: teams travel from their home city to the first stadium, then between consecutive rounds, then back home after the last round.

All data are deterministic integers.

## Input

The input format is:

- Line 1: `n m lambda`
- Next `n` lines: `x_i y_i f_i` for team `i`  
  - `(x_i, y_i)` = home city coordinates
  - `f_i` = fan base size
- Next `m` lines: `sx_j sy_j c_j q_j` for stadium `j`  
  - `(sx_j, sy_j)` = stadium coordinates
  - `c_j` = capacity
  - `q_j` = stadium quality multiplier
- Next line: `B_1 B_2 ... B_{n-1}`  
  `B_r` is the broadcast multiplier of round `r`
- Next `n` lines: an `n × n` integer matrix `R`  
  - `R_{i,i} = 0`
  - `R_{i,j} = R_{j,i}`
  - `R_{i,j}` is the rivalry bonus between teams `i` and `j`
- Next `n - 1` lines: availability strings of length `m`  
  - on round `r`, character `k` is:
    - `'1'` if stadium `k` is available,
    - `'0'` otherwise

Teams are numbered `1..n`, stadiums are numbered `1..m`.

### Guarantees

- `n` is even
- for every round, at least `n / 2` stadiums are available
- all values fit in signed 64-bit arithmetic during judge computation

## Output

Output exactly `n(n-1)/2` lines.

Each line must contain:

`r i j s`

meaning that in round `r`, teams `i` and `j` play at stadium `s`.

### Feasibility requirements

Your output is feasible iff all of the following hold:

- `1 <= r <= n - 1`
- `1 <= i < j <= n`
- `1 <= s <= m`
- every unordered pair `{i, j}` appears exactly once,
- in every round, each team appears in exactly one match,
- stadium `s` is available in round `r`,
- in every round, each stadium is used at most once.

If the output is infeasible or malformed, the score for that test is `0`.

## Objective

For a match between teams `i` and `j` in round `r` at stadium `s`:

- match demand:
  
  `D(i,j) = f_i + f_j + R_{i,j}`

- realized attendance:
  
  `A(i,j,s) = min(c_s, D(i,j))`

- match revenue:
  
  `Rev(i,j,r,s) = B_r * q_s * A(i,j,s)`

Total revenue is the sum of `Rev` over all matches.

### Travel cost

Distance is **Manhattan distance**.

For points `(x1, y1)` and `(x2, y2)`:

`dist = |x1 - x2| + |y1 - y2|`

For each team, let the stadiums it visits in rounds `1..n-1` be `S_1, S_2, ..., S_{n-1}`.

Its travel is:

- home city to `S_1`,
- `S_r` to `S_{r+1}` for all `1 <= r < n - 1`,
- `S_{n-1}` back to home city.

Total travel is the sum over all teams.

### Objective value

You must **maximize**:

`OBJ = TotalRevenue - lambda * TotalTravel`

## Scoring

Let:

- `OBJ_you` = your feasible objective value on the test
- `OBJ_base` = objective value of the **baseline schedule** defined below
- `LB = -lambda * n^2 * Delta`

where `Delta` is the maximum Manhattan distance between any two locations among all team home cities and all stadiums.

`LB` is a valid lower bound for every feasible schedule.

The score for one test is:

`Score_test = 100 * clamp(0, 2, (OBJ_you - LB) / (OBJ_base - LB))`

where:

`clamp(a, b, x) = max(a, min(b, x))`

So:

- infeasible output gives `0`,
- matching the baseline gives `100`,
- beating the baseline gives more than `100`,
- scores are capped at `200` per test.

The final score is the arithmetic mean of `Score_test` over all tests.

### Baseline schedule

The baseline is deterministic:

1. **Pairings by the circle method**
   - Start with the list `[1, 2, ..., n]`.
   - In each round:
     - pair first with last, second with second-last, and so on.
     - then keep the first team fixed and rotate the remaining `n-1` teams one step to the right.

2. **Stadium assignment inside each round**
   - Let the round's matches be the pairings from step 1.
   - Sort these matches by:
     1. decreasing `D(i,j)`,
     2. increasing `i`,
     3. increasing `j`.
   - Take all available stadiums for that round and sort them by:
     1. decreasing `q_s * c_s`,
     2. decreasing `q_s`,
     3. decreasing `c_s`,
     4. increasing `s`.
   - Assign the `k`-th match in the sorted match list to the `k`-th stadium in the sorted stadium list, for `k = 1..n/2`.

## Constraints

- `4 <= n <= 30`, `n` even
- `n/2 <= m <= 40`
- `0 <= x_i, y_i, sx_j, sy_j <= 10^6`
- `1 <= f_i <= 10^6`
- `1 <= c_j <= 10^6`
- `1 <= q_j <= 100`
- `1 <= B_r <= 100`
- `0 <= R_{i,j} <= 10^6`
- `1 <= lambda <= 10^4`

- Time limit: 2 seconds
- Memory limit: 256 MB

## Example

### Input
```text
4 2 1
0 0 50
8 0 40
0 7 45
8 7 35
0 3 60 3
8 3 60 2
1 3 2
0 10 5 2
10 0 7 4
5 7 0 8
2 4 8 0
11

11
```

### Output
```text
1 1 4 1
1 2 3 2
2 1 3 1
2 2 4 2
3 1 2 1
3 3 4 2
```

### Explanation
This is a feasible schedule:

- every pair meets exactly once,
- each round has two matches and every team plays exactly once,
- both stadiums are available in every round.

The judge computes:

- revenue from round multipliers, stadium quality, stadium capacity, and match demand,
- travel from each team's home city through its sequence of assigned stadiums and back home.

Your objective is `TotalRevenue - TotalTravel` here because `lambda = 1`.

Different approaches can work well: constructing strong round-robin pairings, assigning premium matches to high-value rounds, clustering teams geographically across consecutive rounds, or using local search / metaheuristics to trade revenue against travel.
