# Build Battle Supply Depot Design

## Problem

WAPER is preparing for many rounds of Build Battle.

In round `i`, the arena is a line of `n` build positions numbered `1..n`.  
The required wool colors are generated by a repeating pattern with parameter `m_i`:

\[
S_i[j] = ((j-1) \bmod m_i) + 1
\]

So the colors in round `i` are:

`1, 2, ..., m_i, 1, 2, ..., m_i, ...`

Before any rounds begin, you may install some **supply chests** along the line.  
Each chest is placed at one integer position and stores some set of colors.

When WAPER needs the block for position `j` in round `i`:

- if at least one installed chest contains color `S_i[j]`, then the block is fetched from the **nearest** such chest, costing the distance in positions;
- otherwise, that block is considered **missing**, and a fixed penalty `P` is paid for that block.

You must design the chest layout to minimize total cost over all rounds.

Each chest has a capacity limit on how many different colors it may store. Installing chests and loading colors also costs money, so using many chests or storing many colors is not always good.

This is an optimization problem: any feasible solution is accepted, and better solutions receive higher scores.

---

## Input

The input contains a single test case.

The first line contains seven integers:

\[
n,\ q,\ K,\ B,\ F,\ G,\ P
\]

- `n` — number of build positions in each round
- `q` — number of rounds
- `K` — maximum number of chests you may install
- `B` — maximum number of colors that may be stored in one chest
- `F` — fixed cost per installed chest
- `G` — cost per `(chest, color)` loading entry
- `P` — penalty for each block whose color is unavailable in all chests

The second line contains `q` integers:

\[
m_1, m_2, \dots, m_q
\]

where round `i` uses the repeating color pattern `1..m_i`.

Let

\[
M = \max_i m_i
\]

be the largest color index that can ever appear.

---

## Output

Your output describes your chest layout.

The first line contains one integer `T` — the number of installed chests.

Then output `T` lines.  
For each chest, output:

\[
x_t\ \ s_t\ \ c_{t,1}\ \ c_{t,2}\ \ \dots\ \ c_{t,s_t}
\]

meaning:

- the chest is placed at position `x_t` (`1 <= x_t <= n`)
- it stores `s_t` colors
- the stored colors are `c_{t,1}, ..., c_{t,s_t}`

### Feasibility requirements

Your solution is **feasible** if all of the following hold:

- `0 <= T <= K`
- for every chest, `1 <= x_t <= n`
- for every chest, `0 <= s_t <= B`
- every stored color satisfies `1 <= c_{t,j} <= M`
- within one chest, all listed colors are distinct

Multiple chests may be placed at the same position.  
A color may be stored in multiple chests.

If the output is infeasible, the score for this test case is `0`.

---

## Objective

For each round `i` and position `j`, let the required color be:

\[
S_i[j] = ((j-1) \bmod m_i) + 1
\]

Let `D(i, j)` be the service cost for that block:

- if some chest stores color `S_i[j]`, then

\[
D(i, j) = \min_{t: S_i[j] \in C_t} |j - x_t|
\]

where `C_t` is the set of colors stored in chest `t`;

- otherwise,

\[
D(i, j) = P
\]

The total cost of your solution is:

\[
\text{Cost}
=
F \cdot T
+
G \cdot \sum_{t=1}^{T} s_t
+
\sum_{i=1}^{q} \sum_{j=1}^{n} D(i, j)
\]

Your goal is to **minimize** `Cost`.

---

## Scoring

For each test case, the official baseline solution is:

- install `0` chests.

Its cost is therefore:

\[
\text{BaseCost} = n \cdot q \cdot P
\]

If your output is infeasible, your score for the test case is `0`.

Otherwise, let your cost be `Cost`.  
Your test-case score is:

\[
\text{Score} =
10^6 \cdot \min\left(10,\ \frac{\text{BaseCost}}{\text{Cost}}\right)
\]

Scores are rounded down to the nearest integer.

The final score over all test cases is the sum of test-case scores.

So:

- matching the baseline gives `1,000,000` points on that test;
- improving the cost gives a proportionally higher score;
- extremely large improvements are capped at `10,000,000` points per test.

---

## Constraints

- `1 <= n <= 3000`
- `1 <= q <= 3000`
- `1 <= n \cdot q <= 6 \times 10^6`
- `1 <= m_i <= n`
- `0 <= K <= 300`
- `1 <= B <= 30`
- `0 <= F, G, P <= 10^9`

### Time limit
4 seconds

### Memory limit
512 MB

---

## Example

### Sample Input
```text
6 2 2 2 2 1 5
2 3
```

### Sample Output
```text
2
2 2 1 2
5 1 3
```

### Explanation

There are two rounds:

- round 1 (`m=2`): `1 2 1 2 1 2`
- round 2 (`m=3`): `1 2 3 1 2 3`

The solution installs:

- a chest at position `2` storing colors `{1,2}`
- a chest at position `5` storing color `{3}`

Installation and loading cost:

- `2` chests × `F=2` → `4`
- `3` stored entries × `G=1` → `3`

So fixed cost is `7`.

Then each block pays the distance to the nearest chest containing its color:

- round 1 service cost = `11`
- round 2 service cost = `9`

Total cost = `7 + 11 + 9 = 27`.

The baseline installs no chests, so every one of the `6 × 2 = 12` blocks pays penalty `5`:

\[
\text{BaseCost} = 60
\]

Thus the sample score would be based on:

\[
10^6 \cdot \min\left(10,\frac{60}{27}\right)
\]

At a high level, good solutions must balance:

- opening more chests vs. paying chest cost,
- storing more colors vs. paying loading cost,
- replicating popular colors in multiple places vs. saving capacity,
- leaving rare colors uncovered and paying penalty `P`.
