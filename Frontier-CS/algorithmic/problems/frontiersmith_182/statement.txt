# High-Contrast Banner Assembly

## Problem

A festival is building a giant black-and-white LED banner from binary strips.

You are given `m` binary strings `s_1, s_2, ..., s_m`, each of the same even length `n`.  
Each string contains exactly `n/2` zeroes and `n/2` ones.

Before mounting the strips, you may **modify each strip at most once**:

- choose one contiguous substring of that strip and reverse it, or
- leave the strip unchanged.

After all chosen reversals, you must arrange the `m` strips in some order to form an `m × n` binary matrix.

The visual quality of the banner is measured by how often neighboring LEDs are different:

- **horizontal contrast**: inside each row, neighboring cells in columns `j` and `j+1`,
- **vertical contrast**: between consecutive rows, cells in the same column.

These contrasts are weighted.

Your task is to output a feasible arrangement and set of reversals that maximize the total weighted contrast.

This is an **optimization problem**: better solutions receive higher scores.

---

## Input

The first line contains a single integer `t` — the number of test cases.

For each test case:

- The first line contains two integers `m` and `n` (`n` is even).
- The second line contains `n-1` integers `h_1, h_2, ..., h_{n-1}`:
  the horizontal weights.
- The third line contains `n` integers `v_1, v_2, ..., v_n`:
  the vertical weights.
- Each of the next `m` lines contains one binary string `s_i` of length `n`.

For every strip `s_i`:

- `s_i` contains only `0` and `1`,
- `|s_i| = n`,
- `s_i` has exactly `n/2` zeroes and `n/2` ones.

---

## Output

For each test case, output:

1. One line with a permutation `p_1 p_2 ... p_m` of `1..m`, the order in which the strips are placed from top to bottom.
2. Then `m` lines, one for each original strip `i = 1..m`, describing the reversal applied to that strip:
   - output `0 0` to leave strip `i` unchanged, or
   - output `l_i r_i` with `1 <= l_i < r_i <= n` to reverse the substring `s_i[l_i..r_i]` (1-indexed, inclusive).

### Feasibility rules

A solution for a test case is **feasible** iff:

- `p` is a valid permutation of `1..m`;
- for every strip `i`, the pair is either `0 0` or valid indices `1 <= l_i < r_i <= n`.

If a test case output is infeasible, that test case receives score `0`.

### Construction of the final matrix

For each strip `i`:

- if `l_i = r_i = 0`, let `t_i = s_i`;
- otherwise, let `t_i` be `s_i` after reversing substring `s_i[l_i..r_i]`.

The final matrix rows are:

- row `1` = `t_{p_1}`
- row `2` = `t_{p_2}`
- ...
- row `m` = `t_{p_m}`

---

## Objective

For a constructed matrix `A` of size `m × n`, define its total contrast value:

\[
\text{Obj} =
\sum_{r=1}^{m}\sum_{c=1}^{n-1} h_c \cdot [A_{r,c} \ne A_{r,c+1}]
+
\sum_{r=1}^{m-1}\sum_{c=1}^{n} v_c \cdot [A_{r,c} \ne A_{r+1,c}]
\]

where `[condition]` is `1` if the condition is true and `0` otherwise.

Your goal is to **maximize** `Obj`.

---

## Scoring

For each test case, define:

- `Base` = the objective value of the **baseline solution**:
  - strips kept in the original input order `1,2,...,m`,
  - no reversals on any strip.
- `Upper` = the trivial upper bound:
\[
\text{Upper} = m \cdot \sum_{c=1}^{n-1} h_c + (m-1)\cdot \sum_{c=1}^{n} v_c
\]
  because every adjacent pair can contribute at most its weight.

If your solution for the test case is feasible and has value `Obj`, then its test-case score is:

- `100`, if `Upper = Base`;
- otherwise
\[
\text{Score} = 100 \cdot \mathrm{clamp}\left(\frac{\text{Obj} - \text{Base}}{\text{Upper} - \text{Base}},\, 0,\, 1\right)
\]
where
\[
\mathrm{clamp}(x,0,1)=\max(0,\min(1,x)).
\]

So:

- matching the baseline gives score `0`,
- improving beyond the baseline gives a proportionally higher score,
- reaching the upper bound gives score `100`,
- doing worse than the baseline still gives score `0`.

The final score is the **average** of test-case scores.

---

## Constraints

- `1 <= t <= 30`
- `1 <= m <= 2000`
- `2 <= n <= 2000`, `n` even
- `1 <= h_c <= 10^6`
- `1 <= v_c <= 10^6`
- total sum of `m * n` over all test cases does not exceed `2 * 10^5`

These limits are chosen so that exhaustive search over permutations and reversal choices is infeasible in practice.

- Time limit: 2 seconds
- Memory limit: 256 MB

---

## Example

### Input
```text
1
3 4
1 2 1
3 1 1 3
0110
1001
0101
```

### Output
```text
3 1 2
2 3
0 0
0 0
```

### Explanation

- Strip `1`: `0110` -> reverse positions `2..3` -> `0011`
- Strip `2`: unchanged -> `1001`
- Strip `3`: unchanged -> `0101`

The final row order is `3, 1, 2`, so the matrix is:

- `0101`
- `0011`
- `1001`

The judge computes the weighted number of unequal horizontal and vertical neighboring pairs from this matrix, compares it to the baseline value for the same test case, and then applies the scoring formula above.
