# Party Photo Lineup

## Problem

Hossam is preparing a large party and wants to publish a sequence of promotional photos.

There are `n` friends, numbered from `1` to `n`. For each friend `i`, a positive integer `p_i` is given — their popularity value.

Some pairs of friends do **not** know each other. Any pair not listed is considered to know each other.

Hossam has room for exactly `K` people in the main photo line. You must choose **exactly `K` distinct friends** and arrange them in **any order**.

Let the chosen lineup be:

`a_1, a_2, ..., a_K`

A contiguous block of the lineup, `a_l, a_{l+1}, ..., a_r`, is called **harmonious** if **every pair of people inside that block know each other**.

Each harmonious block contributes a **buzz value** equal to the sum of popularity values of all people in that block:

\[
\text{buzz}(l,r)=\sum_{j=l}^{r} p_{a_j}
\]

Your goal is to output a lineup maximizing the **total buzz** over **all harmonious contiguous blocks**.

So the objective is:

\[
\text{TotalBuzz}(a_1,\dots,a_K)=
\sum_{1 \le l \le r \le K}
\Bigl[
(a_l,\dots,a_r)\text{ is harmonious}
\Bigr]
\cdot
\sum_{j=l}^{r} p_{a_j}
\]

where `[...]` is `1` if the condition is true, otherwise `0`.

Notes:

- Any block of length `1` is always harmonious.
- Pairs `(x,y)` and `(y,x)` represent the same relationship.
- Repeated unfamiliar pairs in the input should be treated as one pair.

This is an optimization challenge: many different heuristic approaches are possible.

## Input

The first line contains an integer `t` — the number of test cases.

For each test case:

- The first line contains three integers `n`, `m`, and `K`.
- The second line contains `n` integers `p_1, p_2, ..., p_n`.
- Each of the next `m` lines contains two integers `x_i` and `y_i`, meaning friends `x_i` and `y_i` do **not** know each other.

All unfamiliar pairs are undirected.

## Output

For each test case, output one line containing exactly `K` **distinct** integers:

`a_1 a_2 ... a_K`

This is the lineup order.

A submission is **feasible** for a test case if:

- it prints exactly `K` integers,
- each integer is between `1` and `n`,
- all printed integers are distinct.

If a test case output is infeasible, its objective value is treated as `0`.

## Objective

For each test case, maximize:

\[
\text{TotalBuzz}(a_1,\dots,a_K)
\]

defined as the sum of popularity values over all harmonious contiguous blocks of your chosen lineup.

## Scoring

For each test case `c`:

- Let `O_c` be the objective value of your output.
- Let `B_c` be the objective value of the **baseline lineup** defined below.

The baseline lineup is constructed deterministically:

1. Sort all friends by decreasing popularity `p_i`.
2. Break ties by smaller index.
3. Take the first `K` friends.
4. Sort those `K` selected indices in increasing order.
5. Use that order as the baseline lineup.

The score for test case `c` is:

\[
S_c = \frac{O_c}{O_c + B_c}
\]

Since popularity values are positive and `K \ge 1`, we always have `B_c > 0`.

The final score is:

\[
\text{FinalScore} = 10^6 \cdot \frac{1}{t}\sum_{c=1}^{t} S_c
\]

Properties:

- `0 \le S_c < 1`
- Matching the baseline gives `S_c = 1/2`
- Any improvement in `O_c` strictly increases `S_c`

## Constraints

- `1 \le t \le 30`
- `2 \le K \le n \le 5000`
- `0 \le m \le 100000`
- `1 \le p_i \le 10^6`
- `1 \le x_i, y_i \le n`
- `x_i \ne y_i`
- The sum of `n` over all test cases does not exceed `50000`
- The sum of `m` over all test cases does not exceed `200000`

- Time limit: 3 seconds
- Memory limit: 512 MB

## Example

### Input
```text
1
5 4 3
5 4 7 3 6
1 3
2 3
2 5
4 5
```

### Output
```text
1 5 3
```

### Explanation
The chosen lineup is `[1, 5, 3]` with popularity values `[5, 6, 7]`.

Harmonious blocks are:

- `[1]` with buzz `5`
- `[5]` with buzz `6`
- `[3]` with buzz `7`
- `[1,5]` with buzz `11`
- `[5,3]` with buzz `13`

Block `[1,5,3]` is **not** harmonious because friends `1` and `3` do not know each other.

So the objective value is:

\[
5+6+7+11+13=42
\]

The baseline selects the top-3 popularity friends `{1,3,5}` and orders them increasingly as `[1,3,5]`, whose objective value is `31`.

So the case score is:

\[
\frac{42}{42+31} \approx 0.57534
\]

and the final score for this one-test input would be approximately:

\[
575342.47
\]
```
