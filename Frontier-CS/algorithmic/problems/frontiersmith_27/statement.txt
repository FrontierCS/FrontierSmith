# XOR Window Scheduling

## Problem

A monitoring system receives `n` data packets. Packet `i` has a non-negative fingerprint `a_i`.

Before transmission, you may **reorder** the packets arbitrarily. Let the reordered sequence be

`b_1, b_2, ..., b_n`

where `b_j = a_{p_j}` for some permutation `p` of `1..n`.

The system evaluates several types of monitoring windows.  
For a window `b[l..r]` of length at least `2`, define its **collision resistance** as

\[
R(l,r) = \min_{l \le x < y \le r} (b_x \oplus b_y),
\]

where `⊕` is bitwise xor.

You are given `m` window specifications. The `j`-th specification consists of:

- a fixed window length `w_j`
- a positive weight `c_j`

For this specification, every contiguous window of length exactly `w_j` contributes its collision resistance multiplied by `c_j`.

Your task is to output a permutation of the packets that **maximizes the total weighted collision resistance**.

This is an optimization problem: any feasible permutation is accepted, and better permutations receive higher scores.

---

## Input

The first line contains an integer `t` — the number of test cases.

For each test case:

- The first line contains two integers `n` and `m`.
- The second line contains `n` integers `a_1, a_2, ..., a_n`.
- The next `m` lines each contain two integers `w_j` and `c_j`.

### Constraints per test file

- `1 ≤ t ≤ 2000`
- `2 ≤ n ≤ 100000`
- `1 ≤ m ≤ 5`
- `2 ≤ w_j ≤ min(n, 20)`
- `1 ≤ c_j ≤ 1000`
- `0 ≤ a_i ≤ 10^9`
- The sum of `n` over all test cases does not exceed `100000`

---

## Output

For each test case, output one line with `n` distinct integers

`p_1 p_2 ... p_n`

representing a permutation of `1..n`.

This means the reordered sequence is

\[
b_k = a_{p_k}.
\]

### Feasibility requirements

A line is **feasible** if and only if:

- it contains exactly `n` integers,
- each integer is between `1` and `n`,
- every value from `1` to `n` appears exactly once.

If the output for a test case is infeasible, that test case receives objective value `0`.

---

## Objective

For a feasible permutation, define

\[
\text{Obj} = \sum_{j=1}^{m} c_j \cdot \sum_{l=1}^{n-w_j+1} R(l, l+w_j-1),
\]

where

\[
R(l,r)=\min_{l \le x < y \le r}(b_x \oplus b_y).
\]

Your goal is to **maximize** `Obj`.

All computations are done using 64-bit signed integers.

---

## Scoring

For each test case, the judge also computes a **baseline permutation**:

1. Sort the pairs `(a_i, i)` by increasing `a_i`, breaking ties by increasing `i`.
2. Let this stable sorted index order be the baseline permutation.
3. Let `B` be the objective value of that baseline permutation.

If your permutation has objective value `O`, then the score for that test case is

\[
\text{Score}_{case} = \min\left(1000,\; 100 \cdot \frac{O+1}{B+1}\right).
\]

Notes:

- The baseline always scores exactly `100` on that test case.
- Better-than-baseline solutions score above `100`.
- Worse solutions score below `100`.
- Infeasible output gives `Score_case = 0`.

The final score is the arithmetic mean of `Score_case` over all test cases in the test file.

---

## Constraints
- Time limit: 4 seconds
- Memory limit: 256 MB

---

## Example

### Input
```text
1
5 2
1 2 3 4 5
2 1
3 2
```

### Output
```text
2 5 1 4 3
```

### Explanation

The output permutation corresponds to the reordered sequence:

`[2, 5, 1, 4, 3]`

For window length `2`:

- `[2,5]` → `2 xor 5 = 7`
- `[5,1]` → `4`
- `[1,4]` → `5`
- `[4,3]` → `7`

Contribution: `1 * (7 + 4 + 5 + 7) = 23`

For window length `3`:

- `[2,5,1]` → pair xors are `7, 3, 4`, minimum `3`
- `[5,1,4]` → pair xors are `4, 1, 5`, minimum `1`
- `[1,4,3]` → pair xors are `5, 2, 7`, minimum `2`

Contribution: `2 * (3 + 1 + 2) = 12`

So the objective value is:

\[
23 + 12 = 35
\]

The baseline order is the sorted order `[1,2,3,4,5]`, whose objective is `18`, so this example would receive

\[
100 \cdot \frac{35+1}{18+1} \approx 189.47
\]

points on this test case.
