# Lucky Interval Scheduler

## Problem

A city is preparing a multi-day “lucky number” festival.

There are `n` illuminated panels in a row. Panel `i` initially shows a positive integer `a_i`.
A **lucky number** is a positive integer whose decimal representation contains only digits `4` and `7`.

The festival lasts for `T` rounds. In each round `t`:

1. You may apply **at most one** available upgrade card.
2. After that, spectators observe a subarray `[L_t, R_t]`.
3. You earn `W_t × (number of lucky values currently in panels L_t..R_t)` points.

There are `M` upgrade cards. Card `i` can be used **at most once**, only during rounds `S_i..E_i` inclusive.  
If used, it:

- adds `D_i` to every panel in index interval `[l_i, r_i]`,
- consumes `C_i` budget.

You have total budget `B`.

Your task is to choose **which cards to use and in which rounds to use them** to maximize the total festival score.

This is an optimization problem: better solutions receive better scores.

---

## Input

The input describes one test instance.

- The first line contains four integers  
  `n M T B`
- The second line contains `n` integers  
  `a_1 a_2 ... a_n`
- The next `T` lines describe the spectator observations.  
  Line `t` contains three integers  
  `L_t R_t W_t`
- The next `M` lines describe the upgrade cards.  
  Line `i` contains six integers  
  `l_i r_i D_i C_i S_i E_i`

All indices are 1-based.

---

## Output

Output exactly `T` integers `x_1, x_2, ..., x_T`.

- `x_t = 0` means you use no card in round `t`.
- `x_t = i` means you use card `i` in round `t`.

### Feasibility requirements

Your output is **feasible** if all of the following hold:

1. `0 ≤ x_t ≤ M` for every round `t`.
2. Every nonzero card index appears at most once.
3. If `x_t = i`, then `S_i ≤ t ≤ E_i`.
4. The total cost of all used cards is at most `B`.

If any requirement is violated, the submission is considered infeasible and its objective value for that test is `0`.

### Evaluation of a feasible output

Start from the initial array `a`.

For rounds `t = 1..T` in order:

1. If `x_t = i > 0`, add `D_i` to every current array element with index in `[l_i, r_i]`.
2. Let `cnt_t` be the number of lucky numbers in the current subarray `[L_t, R_t]`.
3. Gain `W_t × cnt_t` points.

The objective value is the total gained points over all rounds.

---

## Objective

Maximize

\[
\text{OBJ} = \sum_{t=1}^{T} W_t \cdot cnt_t
\]

where `cnt_t` is the number of lucky numbers in `[L_t, R_t]` **after** applying your chosen card for round `t` (if any).

`OBJ` is always evaluated exactly by the judge.

---

## Scoring

For each test file:

- Let `OBJ_you` be your objective value.
- Let `OBJ_base` be the objective value of the **official baseline algorithm** defined below.

Your score for that file is

\[
\text{Score}_{file} =
10^6 \cdot \mathrm{clamp}\!\left(\frac{OBJ_{you}+1}{OBJ_{base}+1},\,0,\,2\right)
\]

where

\[
\mathrm{clamp}(x,0,2)=
\begin{cases}
0 & x<0 \\
x & 0\le x \le 2 \\
2 & x>2
\end{cases}
\]

The final contest score is the arithmetic mean of `Score_file` over all test files.

### Official baseline algorithm

The baseline simulates rounds from `1` to `T`.  
At round `t`, among all currently unused cards `i` such that:

- `S_i ≤ t ≤ E_i`, and
- `C_i` does not exceed the remaining budget,

it computes the **immediate gain**

\[
gain_i =
W_t \cdot
\Big(
\text{lucky-count in } [L_t,R_t] \text{ after applying card } i
-
\text{current lucky-count in } [L_t,R_t]
\Big)
\]

The baseline chooses the card maximizing:

1. larger `gain_i / C_i`,
2. if tied, larger `gain_i`,
3. if tied, smaller card index.

If the best card has `gain_i > 0`, it is used in round `t`; otherwise the baseline uses no card in that round.

This process continues until round `T`.

---

## Constraints

- `1 ≤ n ≤ 50,000`
- `1 ≤ M ≤ 5,000`
- `1 ≤ T ≤ 5,000`
- `1 ≤ B ≤ 10^9`
- `1 ≤ a_i ≤ 10^4`
- `1 ≤ L_t ≤ R_t ≤ n`
- `1 ≤ W_t ≤ 10^6`
- `1 ≤ l_i ≤ r_i ≤ n`
- `1 ≤ D_i ≤ 10^4`
- `1 ≤ C_i ≤ 10^6`
- `1 ≤ S_i ≤ E_i ≤ T`
- It is guaranteed that even if **all** cards were applied, no array value would exceed `10^4`.

Use 64-bit integers for the objective.

- Time limit: 5 seconds
- Memory limit: 512 MB

---

## Example

### Input
```text
5 3 4 5
2 3 4 5 7
1 5 1
2 4 2
1 3 1
3 5 1
1 2 2 2 1 2
4 5 40 3 2 4
2 5 2 3 1 3
```

### Output
```text
1 2 0 0
```

### Explanation

- Round 1: use card 1, array becomes `[4, 5, 4, 5, 7]`  
  Lucky numbers in `[1,5]`: `4, 4, 7` → `3`  
  Gain: `1 × 3 = 3`

- Round 2: use card 2, array becomes `[4, 5, 4, 45, 47]`  
  Lucky numbers in `[2,4]`: only `4` → `1`  
  Gain: `2 × 1 = 2`

- Round 3: no card  
  Lucky numbers in `[1,3]`: `4, 4` → `2`  
  Gain: `1 × 2 = 2`

- Round 4: no card  
  Lucky numbers in `[3,5]`: `4, 47` → `2`  
  Gain: `1 × 2 = 2`

Total objective value: `3 + 2 + 2 + 2 = 9`.

This output is feasible because each chosen card is used once, within its allowed round window, and the total cost is `2 + 3 = 5`, exactly the budget.
