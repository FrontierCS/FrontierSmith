# Budgeted Segment Reordering

## Problem

A conveyor belt contains `n` items labeled by integers `a1, a2, ..., an`.

You may perform a sequence of **segment reordering operations**. In one operation, you choose a contiguous subarray `[l, r]` and sort the items `a[l..r]` in **non-decreasing** order. Operations are applied **sequentially**, so later operations see the array produced by earlier ones.

Each operation has an energy cost equal to its length:

- cost of sorting `[l, r]` is `r - l + 1`

For each test case, you are given:

- the initial array,
- a maximum number of operations `K`,
- a total energy budget `B`.

Your task is to choose up to `K` segment-sorting operations, with total cost at most `B`, so that the final array has as few inversions as possible.

An **inversion** in an array `c` is a pair of indices `(i, j)` such that `1 <= i < j <= n` and `c[i] > c[j]`.

This is an optimization problem: there may be many feasible outputs, and better outputs receive higher scores.

## Input

The first line contains one integer `t` — the number of test cases.

Each test case consists of two lines:

- the first line contains three integers `n`, `K`, `B`
- the second line contains `n` integers `a1, a2, ..., an`

## Output

For each test case, output one line in the following format:

- `q l1 r1 l2 r2 ... lq rq`

where:

- `0 <= q <= K` is the number of operations you perform,
- each pair `(li, ri)` satisfies `1 <= li <= ri <= n`,
- the operations are applied in the listed order,
- the total cost satisfies  
  `sum(ri - li + 1) <= B`.

If `q = 0`, output a line containing only `0`.

### Feasibility requirements

For a test case, your output is **feasible** if and only if all of the following hold:

1. `q` is an integer with `0 <= q <= K`,
2. exactly `2q` additional integers follow on that line,
3. every segment `[li, ri]` is valid,
4. total cost does not exceed `B`.

If your output for a test case is infeasible, that test case receives score `0`.

## Objective

Let `c` be the array after applying all your operations.

Your objective value is:

- `I(c)` = number of inversions in `c`

You must **minimize** `I(c)`.

## Scoring

For each test case, the judge also computes a deterministic **baseline solution** as follows:

1. Set `c := a`, `remK := K`, `remB := B`.
2. Repeat while `remK > 0` and `remB >= 2`:
   - Find the smallest index `p` such that `c[p] > c[p+1]`.
   - If no such index exists, stop.
   - Let `q` be the largest index such that  
     `c[p] > c[p+1] > ... > c[q]`  
     (a maximal contiguous strictly decreasing run starting at `p`).
   - Let `len := min(q - p + 1, remB)`.
   - If `len < 2`, stop.
   - Sort `c[p .. p + len - 1]` in non-decreasing order.
   - Decrease `remB` by `len` and `remK` by `1`.
3. Let `I_base` be the inversion count of the resulting baseline array.

If your solution is feasible and produces inversion count `I_sub`, then your score for this test case is:

\[
\text{score} = \left\lfloor 10^6 \cdot \min\left(2,\ \frac{I_{base}+1}{I_{sub}+1}\right) \right\rfloor
\]

If your solution is infeasible, the score is `0`.

### Aggregation

If there are multiple test cases, the final score is the arithmetic mean of the per-test scores.

### Notes

- The baseline always scores exactly `1,000,000` on any test case where it is feasible.
- Better solutions score more than `1,000,000`, up to a cap of `2,000,000`.
- Worse solutions still receive partial credit as long as they are feasible.

## Constraints

- `1 <= t <= 50`
- `2 <= n <= 2 * 10^5`
- `1 <= K <= 40`
- `1 <= B <= 4000`
- `1 <= ai <= 10^9`
- Sum of `n` over all test cases does not exceed `2 * 10^5`

## Constraints
- Time limit: 2 seconds
- Memory limit: 512 MB

## Example

Sample input:
```text
1
5 1 3
3 1 2 5 4
```

Sample output:
```text
1 1 3
```

Brief explanation:

- Your single operation sorts the segment `[1, 3]`.
- The final array becomes `[1, 2, 3, 5, 4]`, which has `1` inversion.
- The baseline sorts the first strictly decreasing run `[1, 2]`, producing `[1, 3, 2, 5, 4]`, which has `2` inversions.
- So the score is

\[
\left\lfloor 10^6 \cdot \frac{2+1}{1+1} \right\rfloor
=
1{,}500{,}000
\]

since this is below the cap of `2,000,000`.
