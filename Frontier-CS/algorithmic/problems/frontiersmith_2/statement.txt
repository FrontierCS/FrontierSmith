# Low-Toggle Tour of Fibonacci IDs

## Problem

A controller must display each authorized beacon ID exactly once during a maintenance round.

Each beacon ID is a **binary string** that:

- has no leading zeros,
- contains no consecutive `1` characters.

These are sometimes called **Fibonacci IDs**.

The controller uses a fixed-width LED panel of width `L`.  
If an ID has length smaller than `L`, it is **left-padded with zeros** before being shown.

For example, with `L = 6`:

- `1` becomes `000001`
- `101` becomes `000101`
- `10010` becomes `010010`

The panel starts blank as the all-zero string of length `L`, and must return to blank after the last ID.

Changing bit `j` on the panel costs `c_j` units of energy.  
So the energy needed to switch from displayed string `A` to displayed string `B` is the sum of `c_j` over all positions where `A` and `B` differ.

Your task is to output an order in which to display all given IDs so that the total energy is minimized.

---

## Input

```text
N L
c_1 c_2 ... c_L
s_1
s_2
...
s_N
```

- `N` — number of IDs.
- `L` — panel width.
- `c_j` — cost of toggling bit position `j` (`1` = leftmost, `L` = rightmost).
- `s_i` — the `i`-th authorized ID.

All `s_i` are guaranteed to be:

- distinct,
- binary strings,
- of length between `1` and `L`,
- without leading zeros,
- without consecutive ones.

---

## Output

Output a permutation of the integers `1..N`:

```text
p_1 p_2 ... p_N
```

meaning the controller displays:

1. `s_{p_1}`
2. `s_{p_2}`
3. ...
4. `s_{p_N}`

### Feasibility requirements

A submission is **feasible** iff:

- exactly `N` integers are printed,
- each integer is in `[1, N]`,
- each index appears exactly once.

Otherwise the submission is infeasible and receives score `0` for that test.

---

## Objective

Let `pad(x)` be string `x` left-padded with zeros to length `L`.

Let `0^L` denote the all-zero string of length `L`.

For two length-`L` strings `A` and `B`, define transition cost:

```text
cost(A, B) = sum of c_j over all positions j where A_j != B_j
```

For an output permutation `p_1, p_2, ..., p_N`, the total energy is

```text
E =
cost(0^L, pad(s_{p_1}))
+ sum_{i=1 to N-1} cost(pad(s_{p_i}), pad(s_{p_{i+1}}))
+ cost(pad(s_{p_N}), 0^L)
```

Your objective is to **minimize `E`**.

---

## Scoring

For each test case, define the **baseline order** as sorting the IDs by their numeric value in increasing order (that is, by interpreting each `s_i` as a binary integer).

Let:

- `B` = total energy of the baseline order,
- `E` = total energy of your feasible output.

Then the test score is:

```text
score = 1,000,000 * clamp(B / E, 0, 2)
```

where

```text
clamp(x, 0, 2) = max(0, min(x, 2))
```

So:

- matching the baseline gives `1,000,000`,
- doing better than the baseline gives more than `1,000,000`,
- doing worse gives less than `1,000,000`,
- improvement beyond a factor of `2` is capped.

If the output is infeasible, the score for that test is `0`.

The final score is the arithmetic mean of scores over all test files.

---

## Constraints

- `1 <= N <= 30000`
- `1 <= L <= 90`
- `1 <= c_j <= 10^6`
- All input IDs are distinct and valid Fibonacci IDs.

## Constraints
- Time limit: 5 seconds
- Memory limit: 1024 MB

---

## Example

### Sample input
```text
4 4
1 1 1 1
1
10
100
101
```

### Sample output
```text
1 4 3 2
```

### Explanation

The padded strings are:

- `1   -> 0001`
- `10  -> 0010`
- `100 -> 0100`
- `101 -> 0101`

The sample order is:

```text
0000 -> 0001 -> 0101 -> 0100 -> 0010 -> 0000
```

Its total energy is:

- `0000 -> 0001` : 1
- `0001 -> 0101` : 1
- `0101 -> 0100` : 1
- `0100 -> 0010` : 2
- `0010 -> 0000` : 1

Total `E = 6`.

The baseline numeric order is:

```text
1, 10, 100, 101
```

which gives:

```text
0000 -> 0001 -> 0010 -> 0100 -> 0101 -> 0000
```

with total `B = 8`.

So the sample score would be:

```text
1,000,000 * (8 / 6) = 1,333,333.333...
```

before any contest-specific rounding.
