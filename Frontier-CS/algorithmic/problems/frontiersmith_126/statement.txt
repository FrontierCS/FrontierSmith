# Label Repair for Range-Agreement Workloads

## Problem
You are given a 1-indexed array `A` of length `N`.  
Each position `i` has an edit cost `C_i`.

You may produce a new array `B` of length `N` by changing some values of `A`, subject to a total edit budget.

A workload of `Q` requests is then evaluated on your repaired array `B`.  
Each request compares two index ranges:

- the first range: `[L1, R1]`
- the second range: `[L2, R2]`

and has a type:

- `T = 1` (**match request**): equal values across the two ranges are good
- `T = 0` (**contrast request**): unequal values across the two ranges are good

For a request, every ordered pair `(i, j)` is considered, where:

- `L1 ≤ i ≤ R1`
- `L2 ≤ j ≤ R2`

Note that the two ranges may overlap, and pairs with `i = j` are allowed if the index belongs to both ranges.

Your task is to output any feasible repaired array `B` that maximizes the total weighted satisfaction of all requests.

This is an optimization problem: exact optimality is not required.

## Input
The input format is:

- First line: integer `N`
- Second line: `N` integers `A_1, A_2, ..., A_N`
- Third line: `N` integers `C_1, C_2, ..., C_N`
- Fourth line: integer `BUDGET`
- Fifth line: integer `Q`
- Next `Q` lines: six integers `T, L1, R1, L2, R2, W`

Definitions:

- `A_i` is the original label at position `i`
- `C_i` is the cost of changing position `i`
- `BUDGET` is the maximum allowed total edit cost
- `W` is the positive weight of the request

## Output
Output exactly one line with `N` integers:

`B_1 B_2 ... B_N`

where:

- `1 ≤ B_i ≤ N` for every `i`

### Feasibility
Your output is **feasible** if:

- every `B_i` is an integer in `[1, N]`
- the total edit cost does not exceed the budget:

\[
\sum_{i : B_i \ne A_i} C_i \le \text{BUDGET}
\]

If the output is infeasible or malformed, the submission receives `0` score on that test case.

## Objective
For a request `q = (T, L1, R1, L2, R2, W)`, define

\[
E_q(B) = |\{(i,j) \mid L1 \le i \le R1,\ L2 \le j \le R2,\ B_i = B_j\}|
\]

Let

\[
S_q = (R1-L1+1)(R2-L2+1)
\]

be the total number of ordered pairs in the request.

The contribution of request `q` is:

- if `T = 1`:

\[
\text{value}_q(B) = W \cdot E_q(B)
\]

- if `T = 0`:

\[
\text{value}_q(B) = W \cdot (S_q - E_q(B))
\]

The total objective is:

\[
\text{OBJ}(B) = \sum_{q=1}^{Q} \text{value}_q(B)
\]

Your goal is to **maximize** `OBJ(B)`.

Use 64-bit integers when reasoning about the objective.

## Scoring
Let:

- `BASE` be the objective value of the unchanged array `A`
- `UPPER` be the trivial upper bound

\[
\text{UPPER} = \sum_{q=1}^{Q} W_q \cdot S_q
\]

Since every request contributes at most `W_q * S_q`, we always have:

\[
\text{OBJ}(B) \le \text{UPPER}
\]

For each test case, the score is:

- `0`, if the output is infeasible or malformed
- otherwise, if `UPPER = BASE`, then the score is `1,000,000`
- otherwise:

\[
\text{score} = 1{,}000{,}000 \cdot \max\left(0,\ \frac{\text{OBJ}(B)-\text{BASE}}{\text{UPPER}-\text{BASE}}\right)
\]

The final score of a submission is the arithmetic mean of its per-test-case scores.

This scoring gives:

- `0` points for matching the baseline
- a smooth improvement gradient above the baseline
- `1,000,000` points for reaching the trivial upper bound

## Constraints
- `1 ≤ N ≤ 50,000`
- `1 ≤ Q ≤ 50,000`
- `1 ≤ A_i ≤ N`
- `1 ≤ C_i ≤ 10^9`
- `0 ≤ BUDGET ≤ sum(C_i)`
- `T ∈ {0, 1}`
- `1 ≤ L1 ≤ R1 ≤ N`
- `1 ≤ L2 ≤ R2 ≤ N`
- `1 ≤ W ≤ 10^9`

## Constraints
- Time limit: 4 seconds
- Memory limit: 512 MB

## Example
Sample input:
```text
5
1 2 1 3 2
4 2 3 5 1
4
3
1 1 3 4 5 5
0 1 2 2 4 2
1 2 5 1 5 1
```

Sample output:
```text
2 2 1 3 2
```

Brief explanation:

- Only position `1` was changed: `1 -> 2`
- Total edit cost is `4`, which is within the budget

For this repaired array:

1. Request `1 1 3 4 5 5`  
   Match request on `[1,3]` and `[4,5]`  
   Equal pairs = `2`, contribution = `5 * 2 = 10`

2. Request `0 1 2 2 4 2`  
   Contrast request on `[1,2]` and `[2,4]`  
   Total ordered pairs = `2 * 3 = 6`  
   Equal pairs = `2`, unequal pairs = `4`, contribution = `2 * 4 = 8`

3. Request `1 2 5 1 5 1`  
   Match request on `[2,5]` and `[1,5]`  
   Equal pairs = `8`, contribution = `8`

So the objective is:

\[
10 + 8 + 8 = 26
\]

The unchanged array has objective `20`, and here:

\[
\text{UPPER} = 5\cdot6 + 2\cdot6 + 1\cdot20 = 62
\]

Therefore the sample output scores:

\[
1{,}000{,}000 \cdot \frac{26-20}{62-20} \approx 142857.14
\]

Any other feasible repaired array is also accepted; higher objective gives higher score.
