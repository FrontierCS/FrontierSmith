# Binary Beacon Retuning

## Problem
A communication tower broadcasts a binary beacon string `S` of length `N`.

There are `M` clients. Client `i` requests that a binary signature string `P_i` appear **somewhere** in the final broadcast as a contiguous substring. If client `i` is satisfied, you earn reward `A_i`.

You are allowed to modify the broadcast before transmission. The final broadcast must be a binary string `U` of the same length `N`.  
For each position `j` (`1 <= j <= N`):

- if `U[j] = S[j]`, no cost is paid;
- if `U[j] != S[j]`, you must flip that bit and pay cost `C_j`.

A client is satisfied if its requested string appears at least once in `U` as a contiguous substring.  
If the same pattern appears multiple times, its reward is still counted only once.  
If several clients request identical strings, each of those clients is counted separately.

Your task is to output a modified broadcast `U` that maximizes:

- total reward of satisfied clients
- minus total bit-flip cost

This is an optimization problem: better solutions receive higher scores.

## Input
Input is given in the following format:

```text
N M
S
C_1 C_2 ... C_N
L_1 A_1
P_1
L_2 A_2
P_2
...
L_M A_M
P_M
```

### Definitions
- `N`: length of the broadcast
- `M`: number of clients
- `S`: original binary string of length `N`
- `C_j`: cost to flip position `j`
- For each client `i`:
  - `L_i`: length of requested signature
  - `A_i`: reward for satisfying that client
  - `P_i`: binary string of length `L_i`

## Output
Output exactly one line:

```text
U
```

where `U` is your chosen final broadcast.

### Feasibility requirements
- `U` must be a string of length exactly `N`
- every character of `U` must be either `0` or `1`

If the output is invalid, the submission receives score `0` on that test.

## Objective
For a feasible output `U`, define:

- **FlipCost**  
  \[
  \sum_{j=1}^{N} [U_j \ne S_j] \cdot C_j
  \]

- **Reward**  
  Let client `i` be satisfied if `P_i` appears at least once as a substring of `U`. Then
  \[
  \text{Reward} = \sum_{i=1}^{M} A_i \cdot [P_i \text{ appears in } U]
  \]

- **Objective value**
  \[
  \text{Obj}(U) = \text{Reward} - \text{FlipCost}
  \]

Your goal is to maximize `Obj(U)`.

## Scoring
For each test file:

- Let `B = Obj(S)`, i.e. the objective value of the baseline solution that performs **no edits** and outputs `U = S`.
- Let
  \[
  UPPER = \sum_{i=1}^{M} A_i
  \]
  which is a trivial upper bound on any achievable objective value.

The score for a feasible submission is:

\[
\text{Score} =
\left\lfloor
10^6 \cdot
\frac{\max(0,\ \text{Obj}(U)-B)}
{\max(1,\ UPPER-B)}
\right\rfloor
\]

This value is clamped automatically to the range `[0, 10^6]`.

So:
- matching the baseline gets score `0`,
- improving over the baseline gives a proportional score,
- reaching the theoretical upper bound `UPPER` would score `10^6`.

The final contest score is the **sum** of per-file scores over all official test files.

## Constraints
- `1 <= N <= 200000`
- `1 <= M <= 200000`
- `S` consists only of `0` and `1`
- `1 <= C_j <= 10^9`
- `1 <= L_i <= N`
- `1 <= A_i <= 10^9`
- `P_i` consists only of `0` and `1`
- \(\sum_{i=1}^{M} L_i \le 500000\)

## Constraints
- Time limit: 4 seconds
- Memory limit: 1024 MB

## Example
### Sample Input
```text
8 3
00010010
1 3 1 3 1 3 1 3
3 10
111
4 7
0010
2 4
01
```

### Sample Output
```text
01110010
```

### Explanation
The original string is `S = 00010010`.

The output `U = 01110010` flips positions 2 and 3, so the flip cost is:

- position 2: cost `3`
- position 3: cost `1`

Total flip cost = `4`.

Satisfied clients:
- `111` appears at positions 2..4, reward `10`
- `0010` appears at positions 5..8, reward `7`
- `01` appears at least once, reward `4`

Total reward = `21`, so:

\[
\text{Obj}(U) = 21 - 4 = 17
\]

For the baseline `U = S`:
- `0010` appears
- `01` appears
- `111` does not appear

So:

\[
B = 7 + 4 = 11
\]

Also:

\[
UPPER = 10 + 7 + 4 = 21
\]

Therefore the score for this file is:

\[
\left\lfloor 10^6 \cdot \frac{17-11}{21-11} \right\rfloor = 600000
\]

Finding the true optimum is intended to be computationally difficult; heuristic and approximate methods are expected.
