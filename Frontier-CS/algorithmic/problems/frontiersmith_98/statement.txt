# Warehouse Route Barcodes

## Problem

A warehouse is arranged as an `n × m` grid.  
Each cell must be painted either white (`0`) or black (`1`).

A **route** is a monotone path from the top-left cell `(0, 0)` to the bottom-right cell `(n-1, m-1)` that only moves:

- right to `(r, c+1)`, or
- down to `(r+1, c)`.

For a route `P`, let:

- `w(P)` be its move string over `R` and `D`, of length `n + m - 2`;
- `s(P)` be the binary string obtained by reading the painted colors of all cells visited by `P`, including both endpoints.  
  Therefore `|s(P)| = n + m - 1`.

You are given:

- `k` candidate routes,
- `q` directed comparison requests.

A request `(a, b, w)` means:

- route `a` should have a barcode lexicographically smaller than route `b`,
- and it is better if the first deciding position appears earlier.

For a fixed painting, define the contribution of one request `(a, b, w)` as follows.

Let `L = n + m - 1`.  
Let `t` be the first position such that `s(P_a)[t] != s(P_b)[t]`.

- If no such position exists, the contribution is `0`.
- Otherwise:
  - if `s(P_a)[t] = 0` and `s(P_b)[t] = 1`, the contribution is `w × (L - t)`;
  - if `s(P_a)[t] = 1` and `s(P_b)[t] = 0`, the contribution is `0`.

In other words, a request only earns points when `s(P_a) < s(P_b)` in lexicographic order, and earlier separation earns more.

Your task is to output **any** valid `0/1` painting of the grid that maximizes the total contribution over all requests.

This is an optimization problem: your output is scored by the judge.

---

## Input

The input contains one test instance.

The first line contains four integers:

`n m k q`

- `n`: number of rows
- `m`: number of columns
- `k`: number of routes
- `q`: number of requests

The next `k` lines each contain one route description string `w_i`:

- `|w_i| = n + m - 2`
- each character is either `R` or `D`
- `w_i` must contain exactly `m - 1` letters `R` and exactly `n - 1` letters `D`

The following `q` lines each contain three integers:

`a b w`

meaning a directed request from route `a` to route `b` with positive weight `w`.

Routes are numbered from `1` to `k`.

---

## Output

Output exactly `n` lines.

Each line must be a binary string of length `m`, consisting only of characters `0` and `1`.

The `j`-th character of the `i`-th line is the color of cell `(i-1, j-1)`.

A submission is **feasible** on a test if and only if:

- exactly `n` lines are printed,
- each line has length exactly `m`,
- every character is `0` or `1`.

If the output is infeasible, its objective value on that test is `0`.

---

## Objective

Let `L = n + m - 1`.

For each route, the judge reconstructs its visited cells from the given move string and reads the painted bits along the route to form `s(P)`.

For each request `(a, b, w)`:

1. Find the first position `t` (`0 ≤ t < L`) where `s(P_a)[t] != s(P_b)[t]`.
2. If no such `t` exists, this request contributes `0`.
3. Otherwise, it contributes:
   - `w × (L - t)` if `s(P_a)[t] = 0` and `s(P_b)[t] = 1`,
   - `0` otherwise.

The objective value of your submission is the sum of contributions over all `q` requests.

You must **maximize** this total.

A trivial upper bound used by the scorer is:

`U = L × Σ w_i`

where the sum is over all requests.

---

## Scoring

For each official test instance:

- Let `V` be your objective value.
- Let `U` be the upper bound defined above.
- Let `B` be the baseline value computed by the judge as the maximum objective among the following 6 fixed paintings:

1. all `0`
2. all `1`
3. `cell(i, j) = i mod 2`
4. `cell(i, j) = 1 - (i mod 2)`
5. `cell(i, j) = j mod 2`
6. `cell(i, j) = 1 - (j mod 2)`

The per-test score is

`Score = 100 × clamp((V - B) / max(1, U - B), 0, 1)`

where `clamp(x, 0, 1) = max(0, min(1, x))`.

The final score is the arithmetic mean of per-test scores over all official tests.

Notes:

- Matching the baseline gives score `0` on that test.
- Reaching the upper bound `U` gives score `100` on that test.
- Scores are continuous: small improvements above baseline increase the score proportionally.

---

## Constraints

- `2 ≤ n, m ≤ 60`
- `1 ≤ k ≤ 5000`
- `1 ≤ q ≤ 20000`
- `1 ≤ w ≤ 10^6`
- All route strings in the input are valid monotone routes from `(0,0)` to `(n-1,m-1)`.

Recommended hidden tests will include instances where exhaustive search is completely infeasible.

- Time limit: 2 seconds
- Memory limit: 512 MB

---

## Example

### Sample input
```text
2 3 3 3
RRD
RDR
DRR
1 2 5
2 3 4
3 1 6
```

### Sample output
```text
001
111
```

### Brief explanation

The three route barcodes under this painting are:

- route 1 (`RRD`): `0011`
- route 2 (`RDR`): `0011`
- route 3 (`DRR`): `0111`

So:

- request `(1,2,5)` contributes `0` because the strings are identical,
- request `(2,3,4)` contributes `4 × (4 - 1) = 12` because the first difference is at position `1` and `0 < 1`,
- request `(3,1,6)` contributes `0` because `0111 > 0011`.

Total objective value: `12`.

The judge then compares this value against the baseline value `B` and the upper bound `U = 4 × (5 + 4 + 6) = 60` to compute the normalized score for this test.
