# Bonus Routing on an ID-Locked Conveyor

## Problem

A conveyor stores `n` uniquely labeled containers, one per bay.  
The current bay order is a permutation `a` of `1..n`, where `a_p` is the label currently in bay `p`.

You control the conveyor for exactly `n` days. On day `i`:

- you must choose two labels `x_i` and `y_i` such that  
  `i <= x_i <= y_i <= min(i + s, n)`,
- then you **swap the bays containing labels `x_i` and `y_i`**,
- choosing `x_i = y_i` is allowed and means “do nothing”.

So the operation is based on **labels**, not bay indices.

After all `n` days, the final permutation earns bonus points from client contracts.

Your task is to output a valid sequence of swaps that maximizes the total earned bonus.

### Contract types

There are three types of contracts:

1. **Slot contract** `(u, p, w)`  
   Earn `w` if label `u` finishes in bay `p`.

2. **Order contract** `(u, v, w)`  
   Earn `w` if label `u` finishes in a strictly smaller bay index than label `v`.

3. **Distance contract** `(u, v, d, w)`  
   Earn `w` if `|pos(u) - pos(v)| <= d` in the final permutation.

All contract bonuses are additive.

## Input

The first line contains an integer `t` — the number of test cases.

For each test case:

- The first line contains five integers  
  `n s A B C`
  - `n` — number of labels and bays
  - `s` — strength parameter
  - `A` — number of slot contracts
  - `B` — number of order contracts
  - `C` — number of distance contracts

- The second line contains `n` integers  
  `a_1 a_2 ... a_n` — the initial permutation.

- The next `A` lines each contain three integers  
  `u p w` — a slot contract.

- The next `B` lines each contain three integers  
  `u v w` — an order contract.

- The next `C` lines each contain four integers  
  `u v d w` — a distance contract.

### Guarantees

- `a` is a permutation of `1..n`.
- Contract labels are valid.
- In order and distance contracts, `u != v`.
- Repeated contracts are allowed; their bonuses stack.

## Output

For each test case, output **one line** containing exactly `2n` integers:

`x_1 y_1 x_2 y_2 ... x_n y_n`

where `(x_i, y_i)` is your chosen swap on day `i`.

### Feasibility requirements

For every day `i`:

- `i <= x_i <= y_i <= min(i + s, n)`

If your output for a test case is malformed or any move is invalid, that test case receives objective value `0`.

## Objective

For each test case, the judge simulates your `n` swaps starting from permutation `a`.

Let `pos(u)` be the final bay of label `u`.

Your objective value `F` is the total earned bonus:

- add `w` for every slot contract `(u, p, w)` with `pos(u) = p`,
- add `w` for every order contract `(u, v, w)` with `pos(u) < pos(v)`,
- add `w` for every distance contract `(u, v, d, w)` with `|pos(u) - pos(v)| <= d`.

You must **maximize** `F`.

## Scoring

For each test case:

- Let `F` be your objective value.
- Let `B0` be the baseline value obtained by the **no-op strategy**:
  - on day `i`, choose `x_i = y_i = i`.
- Let `U` be the sum of weights of **all** contracts in that test case:
  - every slot weight,
  - every order weight,
  - every distance weight.

The per-test normalized score is:

- if `U = B0`, then `S = 1`,
- otherwise  
  `S = clamp((F - B0) / (U - B0), 0, 1)`,

where `clamp(z, 0, 1) = max(0, min(1, z))`.

The final score is:

`1,000,000 * (average of S over all test cases)`

So:
- matching the baseline gives score `0` on that test,
- improving over the baseline gives partial credit,
- reaching the trivial upper bound `U` gives score `1` on that test.

## Constraints

- `1 <= t <= 50`
- `1 <= n <= 2 * 10^5`
- `1 <= s <= n`
- `0 <= A, B, C`
- `1 <= w <= 10^9`
- `0 <= d <= n - 1`
- Sum of `n` over all test cases `<= 2 * 10^5`
- Sum of `A + B + C` over all test cases `<= 4 * 10^5`

Use 64-bit integers for objective computation.

- Time limit: 2 seconds
- Memory limit: 512 MB

## Example

### Input
```text
1
4 2 1 1 1
2 1 4 3
4 1 10
1 3 4
2 4 1 6
```

### Output
```text
1 2 2 4 3 3 4 4
```

### Explanation

Initial permutation: `[2, 1, 4, 3]`

Moves:

1. Day `1`, swap labels `1` and `2`  
   permutation becomes `[1, 2, 4, 3]`
2. Day `2`, swap labels `2` and `4`  
   permutation becomes `[1, 4, 2, 3]`
3. Day `3`, do nothing
4. Day `4`, do nothing

Final positions:
- `pos(1)=1`, `pos(2)=3`, `pos(3)=4`, `pos(4)=2`

Contracts:
- slot `(4,1,10)` → not satisfied
- order `(1,3,4)` → satisfied
- distance `(2,4,1,6)` → satisfied because `|3-2|=1`

So the objective value is `F = 10`.

The no-op baseline keeps `[2,1,4,3]`, satisfying only the order contract, so `B0 = 4`.

The trivial upper bound is `U = 10 + 4 + 6 = 20`.

Thus the normalized score on this test is:

`(10 - 4) / (20 - 4) = 6 / 16 = 0.375`
