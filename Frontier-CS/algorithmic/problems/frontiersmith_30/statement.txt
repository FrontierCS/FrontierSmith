# Budgeted Window Reordering

## Problem

You are given an array `A` of length `N`.  
You may **reorder the array only by adjacent swaps**, and you have a total budget of at most `K` such swaps.

After your reordering, many monitoring windows will be inspected.  
For each window `[l, r]`, define its **bubble energy** as follows:

- Consider running standard bubble sort on the subarray `B[l..r]` until it becomes nondecreasing.
- Every time bubble sort swaps two adjacent values `x` and `y`, it adds `x * y` to the energy.
- The bubble energy of the window is the total added value over all swaps.

For a subarray, this is exactly:

\[
E(l,r)=\sum_{l \le i < j \le r,\; B_i > B_j} B_i \cdot B_j
\]

because each inverted pair is swapped exactly once during bubble sort.

You are also given `Q` weighted windows.  
Your goal is to output a final order of the original elements, reachable using at most `K` adjacent swaps, that **minimizes the total weighted bubble energy** over all windows.

Duplicates may exist in `A`, so elements are considered distinct by their original positions.

---

## Input

The input contains one test case.

- The first line contains two integers `N` and `K`.
- The second line contains `N` integers `A1, A2, ..., AN`.
- The third line contains an integer `Q`.
- Each of the next `Q` lines contains three integers `l`, `r`, and `w`, describing a window `[l, r]` with weight `w`.

### Constraints

- `1 <= N <= 5000`
- `0 <= K <= 200000`
- `0 <= Ai <= 100000`
- `1 <= Q <= 5000`
- `1 <= l <= r <= N`
- `1 <= w <= 100000`

---

## Output

Output a permutation `P1 P2 ... PN` of `1..N`.

This means the final array is

\[
B_i = A_{P_i}
\]

### Feasibility requirements

Your output is feasible iff all of the following hold:

1. `P` is a permutation of `1..N`.
2. The number of inversions in `P` is at most `K`:

\[
\#\{(i,j)\mid 1 \le i < j \le N,\; P_i > P_j\} \le K
\]

This inversion count is exactly the minimum number of adjacent swaps needed to transform the original order into `P`.

If the output is malformed or infeasible, the score for that test file is `0`.

---

## Objective

For each query `(l, r, w)`, let

\[
E(l,r)=\sum_{l \le i < j \le r,\; B_i > B_j} B_i \cdot B_j
\]

The total cost is

\[
C = \sum_{q=1}^{Q} w_q \cdot E(l_q,r_q)
\]

Your goal is to **minimize `C`**.

---

## Scoring

Let:

- `C_out` = your total cost
- `C_base` = the total cost of the **baseline solution**, which outputs the identity permutation

\[
P_i = i \quad \text{for all } i
\]

The score for a test file is:

\[
\text{Score} =
\left\lfloor
10^6 \cdot \min\left(10,\; \frac{C_{base}+1}{C_{out}+1}\right)
\right\rfloor
\]

### Notes

- Baseline output always scores exactly `1,000,000`.
- Better solutions score more than `1,000,000`.
- Worse solutions score less than `1,000,000`.
- A perfect zero-cost solution, if possible, is capped at `10,000,000` for that file.
- Final contest score is the sum of scores over all official test files.

---

## Constraints
- Time limit: 6 seconds
- Memory limit: 512 MB

---

## Example

### Sample input
```text
5 2
5 1 4 2 3
3
1 5 1
1 3 2
2 4 1
```

### Sample output
```text
2 1 4 3 5
```

### Explanation

The output permutation is feasible because it has exactly 2 inversions:

- `(2,1)`
- `(4,3)`

so it can be obtained with 2 adjacent swaps, which matches `K = 2`.

The final array is:

\[
B = [1, 5, 2, 4, 3]
\]

Its weighted bubble energies are:

- Query `[1,5]`, weight `1`: energy `57`
- Query `[1,3]`, weight `2`: energy `10`, contributes `20`
- Query `[2,4]`, weight `1`: energy `30`

So:

\[
C_{out} = 57 + 20 + 30 = 107
\]

For the baseline `P = [1,2,3,4,5]`, the original array is `[5,1,4,2,3]`, whose total cost is:

\[
C_{base} = 128
\]

Therefore the sample score would be:

\[
\left\lfloor 10^6 \cdot \frac{128+1}{107+1} \right\rfloor
=
1{,}194{,}444
\]

This is better than the baseline, so it scores above `1,000,000`.
