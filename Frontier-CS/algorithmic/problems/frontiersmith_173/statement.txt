# Avalanche Recalibration

## Problem
Ina has moved her immortal takodachi octopuses from a single trail to a terraced hatchery: an `H × W` grid of cells.  
Each cell contains exactly one octopus.

The octopus in cell `(r, c)` starts with health `a[r][c]`, where `1 <= a[r][c] <= K`.

You may schedule a sequence of **avalanche drops**.  
A drop is described by five integers:

- `r1 c1 r2 c2 d`

with `1 <= r1 <= r2 <= H`, `1 <= c1 <= c2 <= W`, and `1 <= d < K`.

That drop affects every cell inside the axis-aligned rectangle
`[r1..r2] × [c1..c2]`:

- each affected octopus has its health decreased by `d`;
- if health becomes `0` or less, it repeatedly wraps around by adding `K` until it is again in `[1, K]`.

Equivalently, if the current health is `x`, then after the drop it becomes

`((x - d - 1) mod K) + 1`.

Each cell also has an importance weight `w[r][c]`.

A drop has a fatigue cost

`C0 + C1 * d + C2 * area`

where

- `area = (r2 - r1 + 1) * (c2 - c1 + 1)`.

You may use at most `L` drops for each test case.

Your goal is to produce a valid sequence of drops that makes the final octopus healths as close to `K` as possible, while keeping fatigue cost low.

For a final health value `x`, define its **residual**
as the number of additional unit-decrements needed to reach `K`:

- `residual(x) = x mod K`

so `residual(K) = 0`, `residual(1) = 1`, ..., `residual(K-1) = K-1`.

## Input
The first line contains an integer `T` — the number of test cases.

For each test case:

- The first line contains four integers  
  `H W K L`
- The second line contains three integers  
  `C0 C1 C2`
- The next `H` lines each contain `W` integers: the initial health grid `a`
- The next `H` lines each contain `W` integers: the importance grid `w`

## Output
For each test case, output:

- one line with an integer `q` — the number of drops you use
- then `q` lines, each containing  
  `r1 c1 r2 c2 d`

### Feasibility requirements
For every test case:

- `0 <= q <= L`
- each drop must satisfy  
  `1 <= r1 <= r2 <= H`,  
  `1 <= c1 <= c2 <= W`,  
  `1 <= d < K`

If your output for a test case is invalid, that test case receives score `0`.

## Objective
For a test case, let:

- `cost` = sum of fatigue costs of all your drops
- `final[r][c]` = final health in cell `(r, c)` after all drops
- `res[r][c] = final[r][c] mod K`

Your objective value is

`O = cost + sum over all cells of (w[r][c] * res[r][c])`

Lower is better.

## Scoring
For each test case, define the **baseline** as using `0` drops.

Its objective value is therefore

`B = sum over all cells of (w[r][c] * (a[r][c] mod K))`

For your objective value `O`, the per-test score is:

- if the output is invalid: `0`
- else if `B = 0`:
  - score = `1,000,000` if `O = 0`
  - score = `0` otherwise
- else:

`score = round(1,000,000 * clamp(0, 2 - O / B, 2))`

where

`clamp(x, lo, hi) = max(lo, min(x, hi))`.

So:

- matching the baseline gives about `1,000,000`
- improving on the baseline gives more than `1,000,000`
- being worse than twice the baseline gives `0`

The total score of a submission is the sum of per-test scores over all test cases.

## Constraints
- `1 <= T <= 50`
- `1 <= H, W <= 120`
- `2 <= K <= 12`
- `0 <= L <= 2000`
- `0 <= C0, C1, C2 <= 10^6`
- `1 <= a[r][c] <= K`
- `1 <= w[r][c] <= 10^4`
- `sum of H * W over all test cases <= 60000`

- Time limit: 2 seconds
- Memory limit: 256 MB

## Example
### Input
```text
1
2 2 3 3
1 1 0
1 2
3 1
5 2
4 3
```

### Output
```text
2
1 1 1 1 1
1 2 2 2 1
```

### Explanation
Initial health grid:
- row 1: `1 2`
- row 2: `3 1`

Weights:
- row 1: `5 2`
- row 2: `4 3`

Baseline (`0` drops):
- residuals are `1, 2, 0, 1`
- baseline objective  
  `B = 5*1 + 2*2 + 4*0 + 3*1 = 12`

Submitted drops:
1. `(1,1)-(1,1), d=1` changes cell `(1,1)` from `1` to `3`
2. `(1,2)-(2,2), d=1` changes `(1,2): 2 -> 1`, `(2,2): 1 -> 3`

Final health grid:
- `3 1`
- `3 3`

Final residuals:
- `0 1`
- `0 0`

Weighted residual sum:
`5*0 + 2*1 + 4*0 + 3*0 = 2`

Drop costs:
- first drop: `1 + 1*1 + 0*1 = 2`
- second drop: `1 + 1*1 + 0*2 = 2`

Total objective:
`O = 2 + 2 + 2 = 6`

Per-test score:
`round(1,000,000 * (2 - 6/12)) = 1,500,000`
