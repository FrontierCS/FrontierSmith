# Ant Transit Design

## Problem

JOI-kun is redesigning a laboratory for ant experiments.

The laboratory is modeled as an undirected weighted graph. Vertices are junctions, and edges are wooden corridors. Some vertices contain ant colonies, and some vertices contain sugar piles.

After the laboratory is prepared, JOI-kun will clap once.

When JOI-kun claps:

- each ant may walk along corridors,
- each ant may also use any **activated pheromone tube**,
- the total travel distance of one ant must be at most `L`,
- each ant can eat **at most one** sugar cube,
- each sugar cube can be eaten by **at most one** ant,
- many ants may use the same corridor or tube; movement does **not** consume edge capacity.

Before the clap, you may choose which candidate pheromone tubes to activate, subject to a total construction budget `B`.

Your task is to output a set of candidate tubes to activate so that the **maximum possible number of sugar cubes eaten** is as large as possible.

This is an optimization challenge: better solutions receive higher scores.

---

### Formal model

- The lab has `V` vertices and `E` existing undirected edges.
- Existing edge `e` connects `u_e` and `v_e` and has travel length `d_e`.
- There are `P` candidate pheromone tubes.
- Candidate tube `p` connects `a_p` and `b_p`, has travel length `t_p`, and activation cost `c_p`.
- There are `C` ant colonies. Colony `i` is at vertex `x_i` and contains `A_i` ants.
- There are `S` sugar piles. Pile `j` is at vertex `y_j` and contains `H_j` sugar cubes.

After you choose a feasible set of candidate tubes, ants may travel on the graph consisting of:

- all existing edges, and
- the activated candidate tubes.

An ant from colony `i` can eat a sugar cube from pile `j` if and only if the shortest-path distance from `x_i` to `y_j` in that graph is at most `L`.

The number of sugar cubes eaten is then the maximum value of a bipartite matching-with-capacities:

- colony `i` can supply at most `A_i` ants,
- pile `j` can receive at most `H_j` ants,
- flow from colony `i` to pile `j` is allowed iff distance(`x_i`,`y_j`) `<= L`.

Your objective is to maximize this maximum flow value.

## Input

The input contains a single test case.

```text
V E P C S B L
u_1 v_1 d_1
u_2 v_2 d_2
...
u_E v_E d_E
a_1 b_1 t_1 c_1
a_2 b_2 t_2 c_2
...
a_P b_P t_P c_P
x_1 A_1
x_2 A_2
...
x_C A_C
y_1 H_1
y_2 H_2
...
y_S H_S
```

### Meaning

- `V`: number of vertices
- `E`: number of existing corridors
- `P`: number of candidate pheromone tubes
- `C`: number of ant colonies
- `S`: number of sugar piles
- `B`: total budget
- `L`: maximum travel distance per ant

Then:

- each existing corridor line gives endpoints `u_e, v_e` and length `d_e`,
- each candidate tube line gives endpoints `a_p, b_p`, travel length `t_p`, and activation cost `c_p`,
- each colony line gives vertex `x_i` and number of ants `A_i`,
- each sugar line gives vertex `y_j` and number of sugar cubes `H_j`.

Vertices are numbered from `1` to `V`.

Multiple colonies may be on the same vertex. Multiple sugar piles may be on the same vertex.

## Output

Output any feasible solution in the following format:

```text
R id_1 id_2 ... id_R
```

- `R` is the number of activated candidate tubes.
- `id_k` must be distinct integers in `[1, P]`.
- The total activation cost of the chosen tubes must be at most `B`.

If `R = 0`, output just `0`.

A submission is **infeasible** if any of the following holds:

- some chosen ID is out of range,
- some ID appears more than once,
- the total activation cost exceeds `B`,
- the output cannot be parsed as integers in the required format.

Infeasible submissions receive score `0`.

## Objective

For your chosen set of activated tubes:

1. Build the augmented graph using all existing corridors and the activated tubes.
2. Compute shortest-path distances between every colony vertex and every sugar-pile vertex.
3. Create a bipartite graph:
   - source to colony `i` with capacity `A_i`,
   - colony `i` to sugar pile `j` with infinite capacity if distance(`x_i`,`y_j`) `<= L`,
   - sugar pile `j` to sink with capacity `H_j`.
4. Let `M` be the maximum flow value of this network.

Your objective is to **maximize `M`**, the total number of sugar cubes that can be eaten.

All computations use exact integer arithmetic. The objective value fits in signed 64-bit integer range.

## Scoring

Let:

- `M` = your objective value,
- `M0` = the objective value of the **baseline solution** that activates **no** candidate tubes,
- `U = min(sum A_i, sum H_j)`.

Since activating extra tubes cannot reduce reachability, any feasible solution satisfies `M >= M0`.

The score for a test file is:

- if `U = M0`, then the score is `1,000,000`,
- otherwise

```text
score = round(1,000,000 × (M - M0) / (U - M0))
```

clamped to the range `[0, 1,000,000]`.

The final contest score is the average of test-file scores.

### Baseline

The baseline is easy to implement:

- activate no candidate tubes,
- compute the resulting objective value `M0`.

A solution identical to the baseline receives score `0` on that test file.
A solution reaching the upper bound `U` receives score `1,000,000`.

## Constraints

- `2 <= V <= 3000`
- `0 <= E <= 6000`
- `1 <= P <= 4000`
- `1 <= C <= 800`
- `1 <= S <= 800`
- `1 <= B <= 10^12`
- `1 <= L <= 10^9`
- `1 <= u_e, v_e, a_p, b_p, x_i, y_j <= V`
- `u_e != v_e`
- `a_p != b_p`
- `1 <= d_e, t_p, c_p <= 10^9`
- `1 <= A_i, H_j <= 10^9`

## Constraints
- Time limit: 4 seconds
- Memory limit: 1024 MB

## Example

### Sample input
```text
5 4 3 2 2 5 4
1 2 2
2 3 2
3 4 2
4 5 2
1 3 1 3
2 5 1 4
1 5 1 5
1 3
5 2
3 2
4 4
```

### Sample output
```text
1 3
```

### Explanation

Candidate tube `3` connects vertex `1` and vertex `5`, has travel length `1`, and costs `5`, so it fits the budget.

- Total ants: `3 + 2 = 5`
- Total sugar: `2 + 4 = 6`
- Therefore `U = 5`

Without activating any tube:

- colony at `1` can reach pile at `3` (distance `4`) but not pile at `4`,
- colony at `5` can reach both piles (`4` and `2` respectively),

so the baseline value is `M0 = 4`.

With tube `3` activated, all 5 ants can be matched to reachable sugar cubes, so `M = 5`.

Thus the score on this file is full score:

```text
1,000,000 × (5 - 4) / (5 - 4) = 1,000,000
```
