# Terraforming the Toroidal Windway

## Problem

A research agency operates courier drones above a torus-shaped planet.  
The planet surface is an \(r \times c\) grid with wrap-around in both directions:

- rows are numbered \(1\) to \(r\), top to bottom,
- columns are numbered \(1\) to \(c\), left to right,
- row \(0\) means row \(r\), row \(r+1\) means row \(1\),
- column \(c+1\) means column \(1\).

Each cell has a positive integer elevation. Elevation affects local wind, and wind determines how a drone moves.

A drone in cell \((x, y)\) always moves to the next column \(y+1\) (wrapping from \(c\) to \(1\)).  
Among the three candidate cells

- straight: \((x, y+1)\),
- up-right: \((x-1, y+1)\),
- down-right: \((x+1, y+1)\),

it chooses the one with the highest elevation.

If multiple candidates have the same highest elevation, ties are broken in this exact order:

1. straight,
2. up-right,
3. down-right.

Before any drone launches, you may **terraform** up to \(B\) cells by assigning them new elevations.

After terraforming, the agency evaluates many delivery contracts.  
In every contract:

- a drone starts in column \(1\) at a specified row,
- it flies exactly \(\ell\) full laps around the planet, i.e. exactly \(\ell \cdot c\) steps,
- it therefore ends again in column \(1\),
- the closer its final row is to the requested target row, the more value the contract yields.

Your goal is to choose the terraforming edits to maximize the total contract value.

---

### Contract value

Let the final row of a contract be \(f\), and the target row be \(t\).

The circular row distance is

\[
\delta(f,t)=\min\big((f-t)\bmod r,\ (t-f)\bmod r\big).
\]

Let

\[
H=\left\lfloor \frac{r}{2} \right\rfloor.
\]

A contract with weight \(w\) yields

\[
w \cdot (H+1-\delta(f,t)).
\]

So:

- exact target row gives value \(w(H+1)\),
- farther rows give less,
- even the farthest possible row still gives value \(w\).

## Input

The input describes one test case.

- The first line contains three integers  
  \(r, c, B\) — number of rows, number of columns, and maximum number of cells you may terraform.
- The next \(r\) lines each contain \(c\) integers: the initial elevations.
- The next line contains an integer \(n\) — the number of delivery contracts.
- Each of the next \(n\) lines contains four integers  
  \(s_i, t_i, \ell_i, w_i\):

  - \(s_i\): starting row in column \(1\),
  - \(t_i\): target row in column \(1\),
  - \(\ell_i\): number of full laps,
  - \(w_i\): contract weight.

## Output

Output a terraforming plan.

- The first line must contain one integer \(q\) — the number of edited cells.
- Then output \(q\) lines, each containing three integers  
  \(a_j, b_j, e_j\):

  - row \(a_j\),
  - column \(b_j\),
  - new elevation \(e_j\).

### Feasibility requirements

A submission is feasible if and only if all of the following hold:

- \(0 \le q \le B\),
- all edited cells are distinct,
- \(1 \le a_j \le r\),
- \(1 \le b_j \le c\),
- \(1 \le e_j \le 10^9\).

All edits are applied simultaneously to the initial grid.

If the output is infeasible, the objective value for that test case is defined to be **0**.

## Objective

Let \(V\) be the sum of contract values after applying your edits and simulating all contracts on the resulting terrain.

Your goal is to **maximize \(V\)**.

### Simulation details

For each contract independently:

1. Start at row \(s_i\), column \(1\).
2. Repeat exactly \(\ell_i \cdot c\) times:
   - move to the next column,
   - choose among straight / up-right / down-right by highest elevation,
   - use the fixed tie-breaking rule:
     straight, then up-right, then down-right.
3. Let the final row be \(f_i\).
4. Add
   \[
   w_i \cdot (H+1-\delta(f_i,t_i))
   \]
   to \(V\).

## Scoring

For each test case:

- Let \(V\) be your objective value.
- Let \(V_{\text{base}}\) be the objective value of the **baseline solution**:
  - output \(q=0\), i.e. perform no terraforming.
- Let
  \[
  U=(H+1)\sum_{i=1}^{n} w_i
  \]
  be the trivial upper bound obtained if every contract ends exactly at its target row.

The score for the test case is:

\[
\text{score}=
\begin{cases}
10^6, & \text{if } U=V_{\text{base}},\\[4pt]
10^6 \cdot \dfrac{\max(0,\,V-V_{\text{base}})}{U-V_{\text{base}}}, & \text{otherwise.}
\end{cases}
\]

Scores are clamped to the range \([0,10^6]\).

The final score of a submission is the **sum of test-case scores**.

## Constraints

- \(3 \le r,c \le 2000\)
- \(0 \le B \le 500\)
- \(1 \le n \le 200000\)
- \(1 \le \text{initial elevation} \le 10^9\)
- \(1 \le s_i,t_i \le r\)
- \(1 \le \ell_i \le 10^9\)
- \(1 \le w_i \le 10^6\)

## Constraints
- Time limit: 10 seconds
- Memory limit: 1024 MB

## Example

### Sample input
```text
4 4 1
1 2 9 3
3 5 4 8
4 3 2 7
5 8 1 6
3
1 3 1 5
2 4 1 7
4 1 2 4
```

### Sample output
```text
1
1 4 100
```

### Explanation

Here \(r=4\), so \(H=\lfloor 4/2 \rfloor=2\), and each contract value is:

\[
w \cdot (3-\delta).
\]

The sample output changes cell \((1,4)\) to elevation \(100\).

After this edit, each full lap sends any starting row to row \(4\). Therefore:

- contract 1 ends at row \(4\), target \(3\), distance \(1\), value \(5 \cdot (3-1)=10\),
- contract 2 ends at row \(4\), target \(4\), distance \(0\), value \(7 \cdot 3=21\),
- contract 3 makes two full laps and still ends at row \(4\), target \(1\), distance \(1\), value \(4 \cdot 2=8\).

So the total objective value is

\[
V=10+21+8=39.
\]

The baseline plan makes no edits. On the original terrain, one full lap sends every start row to row \(3\), so

\[
V_{\text{base}}=15+14+4=33.
\]

The upper bound is

\[
U=(H+1)\sum w_i = 3 \cdot (5+7+4)=48.
\]

Thus the sample score for this test case is

\[
10^6 \cdot \frac{39-33}{48-33}=400000.
\]
