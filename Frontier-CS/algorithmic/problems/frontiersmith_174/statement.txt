# Hideouts and Corridors

## Problem

lnlhm is trying to organize an emergency escape network in a city.

The city is modeled as a **simple connected undirected graph** with `n` intersections and `m` roads.

- Vertex `i` has a positive integer **rescue value** `w_i`.
- Edge `j` connects two vertices and has a positive integer **construction cost** `c_j`.
- Opening a hideout at any vertex costs a fixed amount `A`.

You may build a network consisting of:

1. A set of **hideout vertices**.
2. A set of **selected roads**.

The selected roads and hideouts must satisfy all of the following:

- Selected roads must be distinct input edges.
- If `F` is the graph formed by all selected roads, then `F` must be a **forest**.
- Let `V_F` be the set of all endpoints of selected roads, together with all hideout vertices.
- Every connected component of the graph `(V_F, selected roads)` must contain **exactly one** hideout.
- Hideout vertices must form an **independent set in the original graph**: no input edge may directly connect two hideouts.

A vertex is considered **rescued** if it belongs to `V_F`, i.e. it is either:

- a hideout, or
- an endpoint of at least one selected road.

Your goal is to choose the hideouts and roads to maximize the total rescued value minus construction and hideout costs.

This is an optimization problem: any feasible solution is accepted, and better solutions receive higher scores.

---

## Input

The input consists of one test case.

- The first line contains three integers `n, m, A`.
- The second line contains `n` integers `w_1, w_2, ..., w_n`.
- The next `m` lines describe the roads.  
  The `j`-th such line contains three integers `u_j, v_j, c_j`, meaning that edge `j` connects vertices `u_j` and `v_j` and has construction cost `c_j`.

Edges are numbered from `1` to `m` in input order.

---

## Output

Output a feasible escape network.

- The first line must contain two integers `r, e`:
  - `r`: number of hideouts,
  - `e`: number of selected roads.
- The second line must contain `r` distinct vertex indices: the hideout vertices.  
  If `r = 0`, output an empty line.
- The next `e` lines must each contain one integer: the ID of a selected edge.

### Feasibility requirements

Your output is **feasible** if and only if all of the following hold:

1. All listed hideout vertices are distinct and in `[1, n]`.
2. All listed edge IDs are distinct and in `[1, m]`.
3. No two hideouts are adjacent in the original graph.
4. The selected edges form an acyclic graph.
5. In the graph consisting of:
   - all selected edges, and
   - all vertices incident to selected edges plus all hideout vertices,
   
   every connected component contains exactly one hideout.

If your output is infeasible, its objective value is defined to be `0`.

The empty solution `r = 0, e = 0` is feasible.

---

## Objective

Let:

- `H` be the set of hideout vertices,
- `E'` be the set of selected edges,
- `V'` be the set of all vertices that are either in `H` or incident to at least one edge in `E'`.

Your objective value is

\[
O = \sum_{v \in V'} w_v \;-\; \sum_{j \in E'} c_j \;-\; A \cdot |H|.
\]

You must **maximize** `O`.

Because the empty solution is feasible, the best strategy will never need to output a negative objective.

---

## Scoring

For each test case, the judge computes:

- `O`: your objective value,
- `W = \sum_{i=1}^{n} w_i`,
- `B`: the objective value of the **baseline solution** defined below.

### Baseline solution

The baseline uses **no roads** and only chooses singleton hideouts by the following greedy rule:

1. Sort all vertices by:
   - decreasing `w_i`,
   - breaking ties by smaller vertex index.
2. Start with an empty hideout set `H`.
3. In that order, add vertex `v` to `H` if:
   - `w_v > A`, and
   - `v` is not adjacent to any vertex already in `H`.
4. Output hideouts `H` and no selected edges.

Its objective is:

\[
B = \sum_{v \in H}(w_v - A).
\]

### Per-test score

The score for one test case is:

\[
\text{score} =
\begin{cases}
50 \cdot \dfrac{O}{\max(1, B)} & \text{if } O \le B,\\[1.2em]
50 + 50 \cdot \dfrac{O - B}{\max(1, W - B)} & \text{if } O > B.
\end{cases}
\]

Then clamp the result to the range `[0, 100]`.

Thus:

- infeasible or empty poor solutions can score near `0`,
- matching the baseline scores `50`,
- improving beyond the baseline scores between `50` and `100`,
- reaching the theoretical upper bound `W` would score `100`.

### Final score

If there are multiple test files, your final score is the arithmetic mean of the per-test scores.

---

## Constraints

- `1 ≤ n ≤ 20000`
- `n - 1 ≤ m ≤ 100000`
- `1 ≤ A ≤ 10^6`
- `1 ≤ w_i ≤ 10^6`
- `1 ≤ c_j ≤ 10^6`
- The input graph is guaranteed to be simple, undirected, and connected.

- Time limit: 2 seconds
- Memory limit: 512 MB

---

## Example

### Sample input

```text
6 7 4
8 5 6 7 4 9
1 2 2
2 3 2
3 4 3
4 5 1
5 6 2
1 6 5
2 5 2
```

### Sample output

```text
2 4
1 3
1
7
4
5
```

### Explanation

Hideouts are placed at vertices `1` and `3`.

Selected roads are:

- edge `1`: `1 - 2` with cost `2`
- edge `7`: `2 - 5` with cost `2`
- edge `4`: `4 - 5` with cost `1`
- edge `5`: `5 - 6` with cost `2`

These roads form a forest.  
Its connected components are:

- `{1,2,4,5,6}` with hideout `1`
- `{3}` with hideout `3`

The hideouts `1` and `3` are not adjacent in the original graph, so the solution is feasible.

Rescued vertices are `{1,2,3,4,5,6}`, with total value:

\[
8+5+6+7+4+9 = 39
\]

Total road cost:

\[
2+2+1+2 = 7
\]

Hideout cost:

\[
2 \cdot 4 = 8
\]

So the objective is:

\[
O = 39 - 7 - 8 = 24
\]

For this input, the baseline objective is `B = 9`, so this solution scores above the baseline.
